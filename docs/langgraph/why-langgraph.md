# 开篇：LangGraph 到底是个啥

学一个框架之前，我习惯先搞清楚两件事：它解决什么问题，以及我什么时候**不该**用它。
这一篇就是干这个的。

## 一句话版本

> LangGraph 是一个**低级别的编排框架**，用来构建、管理和部署长时间运行的有状态智能体（Agent）。

关键词有两个：**低级别** 和 **有状态**。

- **低级别**：它不帮你管提示词，不规定你的 Agent 必须长什么样。它给的是积木，不是成品。
- **有状态**：它专门解决"跑到一半断了怎么办""下一轮对话还记不记得上一轮""人想中途插一句"这类问题。

官方给的背书是 Klarna、Replit、Elastic 这些公司在用。不过说实话，看框架选型，
我更关心它把哪些脏活包了、哪些留给你。

## 它和 LangChain 是什么关系

这个我一开始是真绕。简单理一下：

- **LangChain**：一堆可组合的组件——模型封装、工具、检索器、提示模板。写 LLM 应用的"零件库"。
- **LangGraph**：把这些零件**编排**起来的运行时。它是图（Graph）执行引擎。
- **LangSmith**：可观测性 / 评估平台，帮你调试和追踪。

LangGraph **可以独立使用**，不装 LangChain 也行（模型调用自己写）。
但它俩配合最顺：LangChain 提供模型和工具，LangGraph 负责让它们按你的流程转起来。

::: tip 顺带一提
文档里还提到有 JS 版本（`langgraphjs`），本栏目的笔记都是 Python 版。
:::

## 为什么不直接用 while 循环写 Agent

我第一次写 Agent 的时候确实就是这么干的：

```python
messages = [system_prompt, user_input]
while True:
    response = llm.invoke(messages)
    if not response.tool_calls:
        break
    messages.append(response)
    for call in response.tool_calls:
        messages.append(execute(call))
```

跑 demo 完全没问题。然后需求一来就崩了：

1. **跑到一半挂了**：进程重启，上下文全没了，用户得从头再来。
2. **想加人工审核**："调用支付接口之前必须人工确认"——while 循环里怎么插一脚？插了之后怎么从原地继续？
3. **想记住跨会话的信息**："这个用户不喜欢啰嗦"——存哪？什么时候读？
4. **流程不是线性的**：要并行跑三个子任务、要反思重试、要多个 Agent 互相转交——`if/else` 写到后面自己都看不懂。
5. **没法调试**：出错了只知道"最后挂了"，不知道第几步的状态是什么。

LangGraph 的核心价值就是把这五条都变成"配置一下就行"的事。

## 核心优势（文档总结的五条，我逐条翻译成人话）

| 官方说法 | 我的理解 |
| --- | --- |
| **持久执行**（durable execution） | 每一步都存快照，挂了从上次中断处继续，不用重跑 |
| **人机协作**（human-in-the-loop） | 任意时间点可以暂停，让人看一眼、改一下，再接着跑 |
| **全面记忆** | 短期（同一会话内的上下文）+ 长期（跨会话的用户画像）都给了机制 |
| **LangSmith 调试** | 有可视化能看每一步的状态迁移（这个我没怎么用，但看图确实直观） |
| **生产就绪部署** | 有配套的 LangGraph Platform / Studio |

另外还有两个我觉得很实在的点：

- **一流的一等公民流式支持**：token 级、步骤级都能流出来。
- **低层级可扩展**：没有"框架觉得你不需要"然后就不给你开口这种情况，自定义空间很大。

## 什么时候**不**该用它

这是我个人的判断，文档没这么写：

- **一次性调用**：就问个问题、转个格式，直接调模型 API 或者用 LangChain 的 chain 就够了。
  上 LangGraph 属于杀鸡用牛刀，光理解 State/Node/Edge 就要花半天。
- **纯同步的固定流水线**：流程完全确定、不需要断点续跑、不需要人工介入——
  写个普通函数调用链更清楚。
- **团队没人维护**：它是个活跃但仍在快速演进的项目，API 会变。承诺了就得跟版本。

## 生态位

```
LangChain（零件）──→ LangGraph（编排运行时）──→ LangGraph Platform / Studio（部署+可视化）
                                └──→ LangSmith（追踪评估）
```

独立可用，但配上全家桶更省事。

## 小结

- LangGraph = 有状态工作流 / Agent 的**底层执行引擎**。
- 它不规定你的架构，只负责状态、断点、记忆、流式这些底层能力。
- 想清楚自己是不是真的需要"长时间运行 + 有状态"，再决定上不上。
