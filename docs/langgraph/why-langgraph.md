# 开篇：LangGraph 的定位

选型之前需要明确两件事：该框架解决什么问题，以及在什么情况下**不**应使用它。

## 一句话定义

> LangGraph 是一个**低级别的编排框架**，用于构建、管理和部署长时间运行的有状态智能体（Agent）。

定义包含两个关键词：**低级别**与**有状态**。

- **低级别**：不接管提示词，不限定智能体形态，提供的是基础构件，成品方案留给用户。
- **有状态**：专门处理执行中断后的恢复、多轮对话的上下文延续、人工中途介入等问题。

官方列举的用户包括 Klarna、Replit、Elastic 等企业。就选型而言，更值得关注的是
框架究竟封装了哪些能力、又将哪些部分留给开发者。

## 与 LangChain 的关系

三者常被混淆，此处作简要区分：

- **LangChain**：可组合的组件库——模型封装、工具、检索器、提示模板，即 LLM 应用的"零件库"。
- **LangGraph**：将上述组件**编排**起来的运行时，本质上是一个图（Graph）执行引擎。
- **LangSmith**：可观测性与评估平台，用于调试和追踪。

LangGraph **可独立使用**，不依赖 LangChain 亦可运行（模型调用自行实现）。
但两者配合最为常见：LangChain 提供模型与工具，LangGraph 负责按既定流程调度。

::: tip 补充
文档另提供 JS 版本（`langgraphjs`），本栏目所有示例均为 Python。
:::

## 为何不直接用循环实现智能体

一种常见的简易实现如下：

```python
messages = [system_prompt, user_input]
while True:
    response = llm.invoke(messages)
    if not response.tool_calls:
        break
    messages.append(response)
    for call in response.tool_calls:
        messages.append(execute(call))
```

用于演示完全可行，但需求一旦复杂化即暴露出结构性缺陷：

1. **执行中断**：进程重启后上下文全部丢失，用户须从头开始。
2. **人工审核**：「调用支付接口前须人工确认」在循环中难以插入，且插入后无法从断点续跑。
3. **跨会话记忆**：「该用户偏好简洁表达」应存储于何处、何时读取，均无着落。
4. **非线性流程**：并行子任务、反思重试、多智能体互相转交等场景下，
   条件分支将迅速失控，可维护性急剧下降。
5. **可观测性缺失**：故障时仅知"最终失败"，无法还原中间各步的状态。

LangGraph 的核心价值，正在于将上述五项从"需要自行设计"变为"配置即可获得"。

## 核心能力

官方归纳为五项，逐条说明如下：

| 官方表述 | 含义 |
| --- | --- |
| **持久执行**（durable execution） | 每步保存快照，故障后可从中断处恢复，无需重跑 |
| **人机协作**（human-in-the-loop） | 可在任意时间点暂停，供人工审查或修改，随后继续执行 |
| **全面记忆** | 短期记忆（会话内上下文）与长期记忆（跨会话画像）均有对应机制 |
| **LangSmith 调试** | 可视化追踪状态迁移与执行路径 |
| **生产就绪部署** | 配套 LangGraph Platform / Studio 等部署设施 |

此外还有两项值得关注：

- **一等公民的流式支持**：支持 token 级与步骤级的实时输出。
- **低层级可扩展**：不作过度封装，自定义空间较大。

## 不适用场景

以下判断源于实践总结，文档并未如此表述：

- **单次调用**：仅需问答或格式转换时，直接调用模型 API 或使用 LangChain 的 chain 即可。
  引入 LangGraph 属于过度设计，仅理解 State / Node / Edge 就需投入相当成本。
- **完全确定的同步流水线**：流程固定、无需断点续跑、无人工介入时，
  普通的函数调用链更为清晰。
- **无力跟进版本的团队**：该项目演进较快，接口存在变更可能，采用即意味着持续跟进。

## 生态位

```
LangChain（组件）──→ LangGraph（编排运行时）──→ LangGraph Platform / Studio（部署与可视化）
                              └──→ LangSmith（追踪与评估）
```

可独立使用，与配套产品组合使用则更为省力。

## 小结

- LangGraph 是有状态工作流与智能体的**底层执行引擎**。
- 它不规定架构，只负责状态、断点、记忆、流式等底层能力。
- 应先确认自身是否真正需要"长时间运行 + 有状态"，再决定是否采用。
